设计原则

清晰的仓库边界与可验证的构建过程

保持仓库职责单一

每个仓库只负责一类明确的职责，避免功能混杂。

内核仓库不包含用户态包管理器源码

内核与用户态代码严格分离，各自独立维护。

通过稳定的内核接口集成

用户态项目通过稳定的内核接口与系统集成。

构建过程可复现

构建过程应可复现，并适合自动化验证。

仓库边界

  • KERNEL 不包含用户态包管理器源码。
  • KERNEL/okrapm/ 仅用于通过 Kbuild 集成 OkraPM 内核模块和内核接口。
  • 用户态 Lunar、OAA、OPSIS 及事务管理代码只维护在独立的 okrapm 仓库。
  • rootfs、系统服务和镜像生成逻辑只维护在 okra-linux 仓库。

自举工具包

自举体系的总入口，收录包管理工具链、构建脚本与基础 OAA 软件包，用于在 aarch64 环境把一个空白系统逐步拉起为可自我演进的发行版。

组件 版本 说明
glibc 2.43-1 系统基座，所有动态程序都依赖它，必须最先安装
gcc 16.2.0-2 自托管编译器，已完成自举闭环
make 4.4.1 构建工具，位于自举仓库 oaa 目录内
coreutils 9.6-1 一百零六个基础命令，文件与文本操作
bash 5.2.37-2 系统默认 shell
KERNEL — 内核项目，基于 Linux 7.2
okrapm — 包管理器 lunar 与 oaa 工具链源码

安装顺序

glibc 优先，其次 gcc；之后 make、bash、coreutils 可任意顺序。

参与开发

请根据变更所属的职责选择对应仓库。请在对应仓库中提交问题和变更。

跨仓库改动应拆分为相互独立、可审核的提交，并在相关仓库中同步说明依赖关系。涉及多个仓库的改动，应分别在各自仓库保持清晰、独立的提交记录。

所有贡献都应遵守相应项目的许可证、代码风格和审核流程。
