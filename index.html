项目组成

Okra 目前由两块代码组成，二者在构建盘上相邻放置。

OkraPM

用户态包管理工具链

  • Lunar：C++17 包管理器，命令行入口
  • OAA 包格式和工具：.oaa 与 .okra
  • OPSIS 安装脚本：POSIX sh 函数库
  • 本地软件源：repo-server HTTP 服务
查看仓库 使用文档

OkraLinux

LiveCD 的构建项目

  • LiveCD 构建：内核、initramfs、rootfs、SquashFS、Limine ISO
  • OKRAINSTALL：跨两次重启的三阶段 TUI 安装器
  • Kanina：可选的 Qt 6 图形安装器
  • 可重复构建：分阶段脚本与 Fedora CI 流水线
查看仓库 构建文档

LiveCD 构建

把 Linux 内核、initramfs、根文件系统、SquashFS 和 Limine BIOS/UEFI ISO 装到一起。

Limine 引导

BIOS 与 UEFI 双支持，ISO 阶段使用 limine/bin/limine。

SquashFS + OverlayFS

只读压缩根文件系统，上层用 OverlayFS 提供可写视图。

systemd 作为 PID 1

系统与服务由 systemd 管理，与常规发行版一致。

流水线顺序

text
build-kernel
build-rootfs
build-coreutils
build-dhcpcd
build-initramfs
build-squashfs
build-iso

在 OkraLinux 仓库里执行 SKIP_QEMU=1 live-build/scripts/build-livecd，ISO 写到 okra-linux-livecd.iso。不设置 SKIP_QEMU=1 时，流水线结束后会执行 test-qemu。

默认安装器 OKRAINSTALL

跨两次重启的三阶段 TUI：分区与复制 Base-OS → 本机配置与驱动 → 账号与时区并清理残留。已安装磁盘使用 GRUB。

Fedora CI 流水线

GitHub Actions 在 Fedora 容器里构建 LiveCD，做出 rootfs 与 BIOS/UEFI ISO，校验后上传为工作流产物。

OkraPM / Lunar

当前入口是 C++17 的 Lunar；OAA 打包脚本是一组 shell 工具。

对象模型

包、组、系统组件和包文件统一为对象，引用写作 命名空间.名字@版本。

事务与快照

改系统状态的操作都进事务，提交前自动建系统快照，失败可回滚。

对象流管道

用 lunar pipe 按 | 组合数据源、过滤、转换与终端操作。

本地软件源

repo-server 扫描归档、抽出元数据拼成索引，再以静态文件对外提供。

常用命令

bash
lunar install GNU.gcc        # 安装包或组
lunar plan install GNU.gcc   # 只预览事务，不执行
lunar list                   # 已安装对象
lunar update                 # 滚动更新
lunar snapshot create "..."  # 创建快照
lunar rollback <id>          # 回滚到快照

参与开发

生成新代码时遵守编码规范；修改旧函数时保持该函数现有缩进和命名。

编码规范

缩进只用 Tab（宽度 4），行宽上限 120；新标识符一律 PascalCase，禁止 camelCase 与 snake_case；对外函数必须有含功能、参数、返回值的文档注释。

不重排旧代码

禁止为对齐风格去重排、重命名旧代码，也不要为风格格式化整个旧文件。

二进制边界

新建的跨动态库、插件或跨语言导出遵守 OAABI：C 链接、PascalCase 符号、失败返回负 errno、聚合类型用指针传递。

按职责选择仓库

跨仓库改动应拆分为相互独立、可审核的提交，并在相关仓库中同步说明依赖关系。
